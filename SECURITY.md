# Security policy

Whoever opens a page or a deck made with our repositories runs our code in their browser, often on files that someone else made. If you find a vulnerability in any of them, please report it privately, through GitHub's [private vulnerability reporting](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability), so that we can fix it before it is disclosed. A public issue is the wrong place for it, since anyone can read an issue as soon as it is posted.

To report a vulnerability, follow the steps below.

1. Open the repository on GitHub, and click its Security tab (shown as 'Security and quality', under the name of the repository).
2. Click 'Report a vulnerability', and describe the problem, how to reproduce it, and what an attacker could do with it.

Your report is kept private between you and the maintainers until a fix is released.

We release fixes for the latest release of each repository only, and not for older releases. Before 1.0, the latest release is the latest minor version with its patch releases, e.g. 0.2.x.
